# Business Rules — java-class-scanner

## 抽出ルール

### BR-1: 通常メソッドの判定（既存ロジックを維持）
以下のいずれかに該当するメソッドは「通常メソッド」として扱わず、`MethodRecord`抽出の対象外とする:
- メソッド名が`<init>`（コンストラクタ）
- メソッド名が`<clinit>`（静的初期化子）
- メソッド名に`lambda$`を含む（ラムダ実装メソッド）

### BR-2: ソート順（既存ロジックを維持）
- クラス一覧: クラス名の昇順
- メソッド一覧: メソッド名の昇順（クラスごと）
- フィールド一覧: フィールド名の昇順（クラスごと）
- コンストラクタ一覧: 引数の個数の昇順（クラスごと）

### BR-3: パッケージフィルタ（既存ロジックを維持）
`--package`オプションが指定された場合、クラスの完全修飾名が指定されたいずれかのパッケージ名で始まる（前方一致）クラスのみを対象とする。複数パッケージ指定時はOR条件。各パッケージ名指定値は前後の空白をトリムしてから比較する。オプション未指定時は全クラスを対象とする。

## 書式化ルール

### BR-4: 複数値項目のフォーマット別表現（FR-3, Functional Design処理フロー3）
実装インターフェース、各種アノテーション、引数リストなど、値が複数存在しうる項目は:
- CSV/TSV: 既存のデリミタ区切り単一文字列表現を維持する（引数・単純な複数値項目は`, `区切り、引数ごとのアノテーションは引数間`|`・アノテーション間`;`の二重区切り）。
- JSON/YAML: ネイティブな配列（`parameterAnnotations`は配列の配列）として表現する。

### BR-5: 単一値項目は配列化しない
`modifiers`（修飾子）は、ClassGraphが返す単一の文字列表現（例: `public final`）をそのまま保持し、CSV/TSV・JSON/YAMLのいずれにおいても分割・配列化を行わない（本ルールはコード側で明示的に複数値を結合していない項目に適用する）。

### BR-6: null相当値の表現（Functional Design Q3=A）
`superclass`のように値が存在しない場合がある項目は:
- CSV/TSV: 空文字列として出力する（既存挙動を維持）。
- JSON/YAML: 明示的なnull相当値として出力し、キー自体は省略しない。

### BR-7: 出力対象が0件の場合のファイル生成（Functional Design Q2=A）
抽出結果が0件（対象クラスが存在しない、またはパッケージフィルタで全て除外された）場合でも、指定された出力オプション（`--classes-output`等）に対応するファイルは生成する。
- CSV/TSV: ヘッダー行のみを含むファイルとなる（既存挙動を維持）。
- JSON/YAML: 空配列/空シーケンス（`[]`）を含むファイルとなる。

### BR-8: CSV/TSVのヘッダー・追記制御（既存ロジックを維持）
出力種別・出力先ファイル名の組み合わせごとに、同一実行内での初回書き込みかどうかを追跡する。初回書き込み時のみヘッダー行を出力し、2回目以降（複数入力ファイル/ディレクトリを処理する場合）は追記のみを行う。

### BR-9: JSON/YAMLの書き込みタイミングと集約（Application Design Q3=A、既存ロジックとの差異）
JSON/YAML出力は、CSV/TSVのような対象ファイルごとの逐次書き込みを行わない。全対象ファイル/ディレクトリの処理完了後、蓄積された全レコードを1回のみ書き込む。書き込み対象は、全入力を横断したフラットな配列/シーケンスであり、各レコードの`sourcePath`属性で入力元を判別する。

## エラーハンドリングルール

### BR-10: 文字コードの不正値フォールバック（既存ロジックを維持）
`--charset`に指定された値が不正（存在しない文字コード名）の場合、警告を表示（`--quiet`未指定時）した上でUTF-8にフォールバックする。

### BR-11: フォーマット指定の不正値フォールバック（既存ロジックをCSV/TSV/JSON/YAMLの4形式に拡張）
`--format`に指定された値が`csv`/`tsv`/`json`/`yaml`のいずれにも一致しない場合、警告を表示（`--quiet`未指定時）した上でCSVにフォールバックする。

### BR-12: 入出力エラー発生時の部分結果の扱い（Functional Design Q1=A）
複数の対象ファイル/ディレクトリを処理中に、いずれかの対象でスキャンエラー（`IOException`）が発生した場合:
- それ以前に正常処理が完了した対象については、出力（CSV/TSVの場合は既に書き込み済みのファイル内容、JSON/YAMLの場合はそれまでに蓄積されたレコード）を保持し、破棄しない。
- JSON/YAMLについては、エラー発生時点までに蓄積されたレコードをベストエフォートで出力ファイルへ書き込む（CSV/TSVの「エラー前の分は残る」という既存挙動になるべく近づける）。
- エラーメッセージを表示（`--quiet`未指定時）し、プロセス終了コードを1に設定する（既存挙動を維持）。
- 未処理の残り対象ファイル/ディレクトリについては、既存挙動（エラー発生時点で処理を打ち切るか継続するか）を踏襲する。※本ルールは「書き込まれる内容」の扱いを定義するものであり、エラー発生後にスキャンループ自体を継続するか中断するかは既存の`ClassScannerRunner`の例外伝播方式（呼び出し元で`IOException`をキャッチし打ち切る）を踏襲し、変更しない。

## コンソール出力ルール

### BR-13: verbose出力への追加項目（FR-6）
`--verbose`指定時のコンソール出力に、クラスの修飾子（`modifiers`）とクラスアノテーション（`classAnnotations`）の表示を追加する。表示位置は既存の型・親クラス・実装インターフェース・パッケージ情報と同様のブロック内とする。
