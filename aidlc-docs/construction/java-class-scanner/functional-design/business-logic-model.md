# Business Logic Model — java-class-scanner

技術非依存（フレームワーク・ライブラリに依存しない）レベルで、主要な業務処理フローを記述する。

## 処理フロー1: クラス情報スキャン・出力（メインフロー）

1. コマンドライン引数を解釈する（対象ファイル/ディレクトリ一覧、`--verbose`, `--package`, `--classes-output`/`--methods-output`/`--fields-output`/`--constructors-output`, `--format`, `--charset`, `--quiet`）。
2. 引数の非オプション部分（対象ファイル/ディレクトリ）が空の場合は、使用方法を表示して正常終了する（既存挙動を維持）。
3. 存在するファイル/ディレクトリのみを処理対象として列挙する（存在しないパスは無視する。既存挙動を維持）。
4. 出力フォーマット（CSV/TSV/JSON/YAML）を`--format`値から決定する。不明な値は警告の上CSVへフォールバックする（既存のフォールバックパターンを新形式にも拡張）。
5. 出力対象種別（classes/methods/fields/constructors）ごとに、指定されたオプション（`--classes-output`等）が存在するかを判定する。
6. **（改訂: BR-8/BR-9）** 出力フォーマットを問わず、単一の集約書き込みモデルで処理する。対象ファイルを処理するたびに抽出したレコードをメモリ上のリストへ蓄積し、全対象の処理が完了した後に1回だけ出力ファイルへ書き込む。CSV/TSVも当初の逐次書き込みモードから、この集約モデルへ統一された（既存互換性よりコードのシンプルさを優先するユーザー判断による）。
7. 各対象ファイル/ディレクトリについて:
   1. ClassGraphによる静的スキャンを実行する。
   2. スキャン結果が0件の場合、その対象についてはこれ以降の処理（抽出・出力・コンソール表示）をスキップする（既存挙動を維持）。
   3. パッケージフィルタ（`--package`）を適用する（前方一致、複数パッケージ指定時はOR条件）。
   4. フィルタ後のクラス一覧をクラス名順にソートする。
   5. 要求された出力対象種別ごとに、抽出ルール（`business-rules.md`）に従いドメインエンティティ（`domain-entities.md`）へ変換し、メモリ上の集約リストへ追加する。
   6. `--quiet`が指定されていない場合、標準/`--verbose`のコンソール出力を行う。
8. 全対象ファイルの処理完了後、要求された出力対象種別ごとに、蓄積済みのレコード一覧を出力ファイルへ書き込む（フォーマット問わず1回のみ）。蓄積済みのレコードはたとえ0件であっても、CSV/TSVはヘッダーのみ、JSON/YAMLは空配列/空シーケンスとして書き込む（`business-rules.md` BR-7参照）。
9. 処理中に入出力エラーが発生した場合、エラーメッセージを表示（`--quiet`未指定時）した上で、それまでに蓄積できた分の出力をベストエフォートで書き出し（フォーマット問わず共通、`business-rules.md` BR-12参照）、終了コードを1に設定する。

## 処理フロー2: コンソール出力（標準/verbose）

- 標準モード: クラス名のみを一覧表示する（既存挙動を維持）。
- `--verbose`モード: クラス名に加え、型・親クラス・実装インターフェース・パッケージ・**修飾子・クラスアノテーション（FR-6で新規追加）**・フィールド一覧・メソッド一覧・コンストラクタ一覧を表示する。

## 処理フロー3: フォーマット別の値表現の切り替え

同一のドメインエンティティ（`ClassRecord`等）から、出力フォーマットに応じて以下のように値表現を切り替える:

| データ種別 | CSV/TSV | JSON/YAML |
|---|---|---|
| 複数値項目（interfaces, parameters, 各種annotations等） | デリミタ区切りの単一文字列（既存挙動を維持） | ネイティブな配列/シーケンス |
| ネスト複数値項目（parameterAnnotations） | 二重デリミタ区切りの単一文字列（既存挙動を維持: 引数間は`|`、引数内アノテーション間は`;`） | 配列の配列（引数ごとに1つの配列） |
| 値なし（任意）項目（superclass等） | 空文字列 | 明示的なnull相当値 |
| 単一値項目（modifiers等） | 文字列そのまま | 文字列そのまま（配列化しない） |

## 処理フロー4: 複数入力の集約キー（改訂: 全フォーマット共通）

複数の入力ファイル/ディレクトリを指定した場合、出力（CSV/TSV/JSON/YAML共通）は各入力を区別する専用の階層構造を持たず、全レコードを1つのフラットな並び（CSV/TSVは行、JSON/YAMLは配列/シーケンス）にまとめる。各レコードが保持する`sourcePath`属性/列が、そのレコードの入力元を示す（当初JSON/YAMLのみに適用されていたApplication Design Q3=Aの方針を、BR-8/BR-9改訂によりCSV/TSVにも拡張）。
